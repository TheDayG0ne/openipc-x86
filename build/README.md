# Experimental x86 build

Run `./build/build.ps1` from the monorepo root on Windows with Git, PowerShell and Docker Desktop (Linux containers). This initializes the public pinned submodules and builds using the current checkout. See the [root README](../README.md) for prerequisites, source pins, output and limitations. The script mounts the checkout read-only, stages sources in the container, and fetches Buildroot 2024.02.10 tag object `4235e198768df7d2696f49f28b090c08fed79954` and verifies its peeled commit `c9620ac37e658d177821be85b4c9484e71e19710`. Firmware's GENERAL external tree is staged and adapted for multiple external trees; upstream submodule files are not modified. The same pipeline stages the WebUI source and installs its unminified `www` tree at `/usr/share/divinus-webui` via a Buildroot package. No reverse proxy or server configuration is installed; serving and WebUI/CGI functionality depend on separate Divinus work and remain unvalidated. No local source URLs or absolute host paths need configuring.

The external configuration targets `bzImage`, `rootfs.squashfs` and `rootfs.ext4`, and applies `overlay/overlay` after the board overlay. Building does not establish bootability, hardware support, persistence or security. The disk-image tool is not run automatically: it requires privileged loop devices and mounts, and Docker Desktop's privileged container would have broad host access. For experimental raw (IMG) and VMDK creation, copy `bzImage` and `rootfs.squashfs` into a trusted isolated Linux VM and follow [image/README.md](../image/README.md). No ISO is provided.

The Ubuntu helper requires a new output directory outside any checkout; it stages all three artifacts in a unique sibling temporary directory and renames that directory into place only after every `docker cp` succeeds. This prevents stale files from being mixed with a partial result. Run `powershell -NoProfile -File ./build/tests/static.ps1` from the root for offline static checks. Full validation requires a clean clone, submodules, Docker and network. These checks do not replace a build or VM and hardware testing.
