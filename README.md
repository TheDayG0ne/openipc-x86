# Проверка WS-Discovery Divinus

Python 3.9+, только стандартная библиотека. Тесты отправляют исключительно UDP WS-Discovery Probe и не меняют настройки устройств. Проверяйте только разрешённые адреса. Это отдельный репозиторий; исходники Divinus не изменяются.

## Самопроверка клиента

```sh
python -m unittest -v
```

Локальные искусственные UDP fixtures проверяют именно клиент, а не реализацию ONVIF и не доказывают работоспособность Divinus. Другие устройства и сторонние ONVIF-сервисы не подменяются.

## Два или более работающих экземпляра

```sh
python discovery.py --target 192.168.1.101:3702 --target 192.168.1.102:3702 --timeout 3
```

Укажите реальные различные unicast IPv4:port, на которых слушают именно нужные экземпляры Divinus. Каждый из двух раундов посылает каждому адресу отдельный Probe с новым MessageID; ответ должен прийти с указанного IP и порта и содержать соответствующий RelatesTo. Проверяются корректность UUID EPR, его неизменность между раундами и уникальность между экземплярами, непустые HTTP(S) XAddrs, их неизменность и отсутствие пересечений между экземплярами. Ненулевой код выхода означает ошибку или тайм-аут. Клиент не использует multicast: при нескольких экземплярах на одном IP и порту unicast не идентифицирует каждый из них; используйте отдельные IP/network namespaces или отдельные адресуемые UDP-порты. Маршрутизация, сетевые экраны и запуск экземпляров настраиваются пользователем; клиент ничего не запускает и не перенастраивает. Проверка стабильности ограничена двумя Probe, а не перезапусками устройств.
