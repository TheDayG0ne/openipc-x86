# OpenIPC x86 — сборочное окружение

Тестовая сборка Divinus и загрузочного Debian VMDK; `sources/divinus` не изменяется при сборке образа или через Compose. USB UVC, RTSP и ONVIF необходимо проверять на гостевой системе — их работоспособность не гарантирована.

## Сборка загрузочного образа

```powershell
Set-Location D:\OpenIPC-x86\build-environment
.\build-vmdk.ps1
.\run-vm.ps1 -Headless
```

Требуется Docker с Linux engine, возможностью privileged и loop devices. Docker Desktop может не поддерживать необходимую конфигурацию. Разместите Docker VHDX и каталог проекта на D:, если это требование к хранению данных. Скрипт каждый раз собирает бинарник из временной копии исходников, затем создаёт VMDK и SHA256 в `..\tmp\artifacts`. Существующий `openipc-x86.vmdk` не перезаписывается: сначала переместите его и соответствующий SHA256. Не перемещайте и не изменяйте используемый работающей VM диск. Docker-том для временной сборки имеет случайное имя и удаляется только после успешного создания тома.

**Секреты:** при каждой сборке создаются разные пароли root для консоли и для HTTP, ONVIF и RTSP каждой камеры. Они сохраняются в `..\tmp\artifacts\credentials-<случайный ID>\credentials.txt`; каталог получает Windows ACL только для текущего пользователя. Проверьте ACL и шифрование диска и сохраните файл в надёжном хранилище. Он содержит открытые пароли; сам VMDK также чувствителен: в нём хранятся конфигурации камер и хеш пароля root. Не публикуйте, не передавайте и не коммитьте их. ACL на сетевых и нестандартных файловых системах может не обеспечивать ожидаемую защиту. При сбое файл секретов может остаться в каталоге. Пароли тестовые; перед промышленным использованием смените их, защитите сеть и проверьте аутентификацию.

В консоли вход `root` с паролем из файла; serial console доступна через QEMU `-Headless`. DHCP и DNS обеспечиваются systemd-networkd и systemd-resolved. Камеры запускаются при появлении `/dev/video0` … `/dev/video3`, останавливаются при исчезновении и ограничивают частоту повторных запусков при ошибках. Номера устройств могут измениться после переподключения, а видеоустройство может не быть UVC-камерой; нужна проверка и при необходимости настройка правил для конкретного оборудования. После исчерпания лимита ошибок повторное подключение либо `systemctl reset-failed divinus-camera@N; systemctl start divinus-camera@N` позволяет повторить запуск.

Образ использует BIOS/MBR, один раздел ext4 с начала 1 MiB и GRUB с явной записью загрузки по UUID. При сборке необходима поддержка kernel loop partition scan; если устройство раздела недоступно, сборка завершится ошибкой. `grub.cfg` формируется при сборке вручную, поэтому после обновления ядра в госте его нужно обновить, указав существующие файлы ядра и initrd (автоматический `update-grub` может не обнаружить ядро в среде сборки).

`run-vm.ps1` по умолчанию использует VMDK, также принимает существующий `.qcow2` через `-Disk`. Добавление xHCI не подключает физическую USB-камеру к гостю; настройте USB passthrough отдельно. QEMU user networking по умолчанию не открывает сервисы гостя извне — настройте port forwarding самостоятельно. Для VMware/VirtualBox требуется отдельная проверка; OVA не создаётся.

## Другие инструменты

- `docker compose run --rm divinus-build` собирает бинарник из копии исходников в `../tmp/artifacts/divinus`.
- `build-divinus.ps1` собирает непосредственно в дереве исходников (clean/build меняет файлы сборки); параметр `-Docker` использует Docker.
- `make-vm.ps1` создаёт **пустой**, не загрузочный QCOW2 и опционально конвертирует его в VMDK. Он может перезаписать существующие файлы; не применяйте его к нужным дискам.

После загрузки проверьте DNS, `systemctl status systemd-networkd systemd-resolved`, `/dev/video*`, журналы `journalctl -u 'divinus-camera@*'` и RTSP/ONVIF/HTTP. Поддержка UVC и корректность потоков зависят от версии исходников и оборудования.
