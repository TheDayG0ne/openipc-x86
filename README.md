# disk-image-x86 (experimental)

Инструмент готовит **только новые файлы** BIOS/MBR raw и VMDK, не принимает имена устройств и не устанавливает загрузчик на физический диск. Это не релиз: полная загрузка, persistent overlay и перезагрузка пока не подтверждены. Не используйте на продуктивных системах.

## Контракт входов

Нужны `bzImage` и `rootfs.squashfs` из совместимой сборки Buildroot. На момент исследования `buildroot-x86` выдаёт только `rootfs.ext4`, а `overlay-x86` требует squashfs и отдельный ext4. Этот инструмент не превращает ext4 в squashfs и не интегрирует overlay. Корневой squashfs должен содержать совместимый ранний `/init`, который умеет находить `overlay.x86=PARTUUID=<id>` **однозначно**, дожидается устройств и отказывается от неоднозначного совпадения. Текущий `overlay-x86` этого не умеет: он принимает только `/dev/...`. Поэтому с текущими репозиториями полученный образ не загрузится до интеграции этого контракта. Не подменяйте идентификацию на `/dev/vda2`: порядок дисков может измениться.

Ядро должно содержать встроенные драйверы контроллера, диска, MBR, squashfs, ext4, overlayfs, devtmpfs и procfs. Поддерживается только BIOS, не UEFI. На одном госте не подключайте клоны образа одновременно: они имеют одинаковые PARTUUID; для каждой установки создавайте образ заново.

## Сборка на Linux

Требуются root, util-linux (sfdisk, losetup), e2fsprogs, grub-install для i386-pc, qemu-img, coreutils, mount. Скрипт создаёт временный raw-файл в каталоге результата, размечает исключительно его loop-устройство, монтирует только его разделы и отключает loop при выходе. Не запускайте в окружении с недоверенными процессами, способными менять файлы или loop-устройства. Каталог результата должен быть доверенным и находиться на Linux FS с поддержкой разреженных файлов. В Docker понадобятся доступ к loop и mount, как правило `--privileged`: это даёт контейнеру широкий доступ к хосту, поэтому применяйте только в изолированной VM. На Docker Desktop Windows bind mounts могут не поддерживать нужные операции; используйте Linux volume.

```
sudo ./create.sh /path/bzImage /path/rootfs.squashfs /trusted/output-directory
```

Результат — новые `openipc.raw` и `openipc.vmdk`; существующие файлы не перезаписываются. Три раздела: ext4 `/boot`, squashfs `/`, ext4 persistent store (нумерация 1, 2, 3). Дисковый MBR ID случаен; root и overlay адресуются соответствующими PARTUUID. Маркер persistent store соответствует `overlay-x86`. Пароль GRUB и аутентификация ОС не настраиваются. Образ и настройки экспериментальны.

## Проверка

См. `tests/static.sh`. Требуется полноценный boot-тест в QEMU/VM: чистый старт, запись и перезагрузка, reset, отсутствие/перестановка дисков и дубли PARTUUID, проверка VMDK. Пока он не выполнен, готовности нет.
